# 일반 애플리케이션 리뷰 가이드

PROFILE 이 `general` 일 때 code-review-platform 이 읽는다. 다른 프로파일에서도 해당하는 항목은 적용한다.

## 공통 설계
- 점검: 책임이 한곳에 모여 있는가 (한 클래스·함수가 여러 일을 하지 않는가)
- 점검: 설정과 코드가 분리되어 있는가 (호스트, 경로, 계정 하드코딩)
- 점검: 실패 시 동작이 명확한가 (예외 삼킴, 부분 실패 후 계속 진행)
- 점검: 라이브 서비스 변경이면 원칙 4(HA·내결함성)를 적용한다

## Spark (SPARK=yes)
- 배치: 같은 입력으로 재실행해도 결과가 같은가 (파티션 덮어쓰기, 중복 적재)
- 배치: 작은 파일 과다 생성, 불필요한 shuffle, driver 로 collect
- 스트리밍: 체크포인트 경로와 재시작 동작, sink 의 멱등성
- 스트리밍: 지연 데이터(watermark) 처리, 상태 크기 증가

## Bash
- 점검: `set -euo pipefail` 또는 동등한 실패 처리, 변수 인용
- 점검: 파괴적 명령(rm, 덮어쓰기)에 대상 확인·안전장치가 있는가
- 점검: 300줄을 넘으면 Python 전환을 제안한다 (팀 규칙)

## Python
- 점검: 500줄을 넘는 스크립트에 pytest 가 있는가 (팀 규칙)
- 점검: 예외 처리 범위, 리소스 정리(with), 의존성 버전 고정

## 레거시 Java 운영 도구
- 점검: 운영 데이터에 쓰는 작업의 dry-run·확인 단계
- 점검: 자원 해제(try-with-resources), 커넥션·스레드 누수
