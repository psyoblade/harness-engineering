# 리뷰어 공통 출력 형식

code-review-lexical, code-review-platform, code-review-advisor 는 최종 응답을 이 형식으로 반환한다 (파일을 만들지 않는다).

## 형식

```
## 관점: <lexical|platform|advisor>

### 원칙 점검
- 원칙 N: ✅|⚠️|❌|해당 없음 — 근거 1줄

### 지적
- 심각도: 🔴 Critical | 🟠 Major | 🟡 Minor
  위치: [파일명:라인번호]
  재현: 어떤 입력·상태 → 무엇이 실행되어 → 어떤 결과 1줄
  도달 경로: [호출하는 파일명:라인번호] (운영 경로에서 이 코드를 실제로 호출하는 곳)
  발생 조건: 항상 | 특정 입력 | 특정 환경(동시성·장애·부하) | 이론상
  구분: 신규 | 기존
  신뢰도: 0~100
  내용: 무엇이 문제인지 1줄
  근거: diff 나 코드에서 확인한 사실 1줄
  제안: 수정 방향 1줄
```

지적이 없으면 `### 지적` 아래에 `지적 없음` 한 줄.

## 심각도 기준 (영향 × 발생 조건)
| 등급 | 조건 |
| --- | --- |
| 🔴 Critical | 재현과 도달 경로를 코드로 확인했고, 영향이 장애·데이터 손실·보안이며, 발생 조건이 항상·특정 입력·특정 환경 |
| 🟠 Major | 영향은 크지만 도달 경로를 끝까지 확인하지 못했거나, 드문 환경에서만 발생 |
| 🟡 Minor | 발생 조건이 이론상(상위에서 이미 막힘 등)이거나 영향이 작음 |

- 🔴 는 재현, 도달 경로, 발생 조건을 모두 채워야 한다. 하나라도 비면 🟠 이하로 쓴다.
- 🟠 🟡 는 재현, 도달 경로를 모를 때 `확인 못 함` 으로 쓴다.
- 도달 경로는 `[파일명:라인번호]` 형식으로 쓴다 (verify-locations.sh 가 실재 여부를 검사한다). 이 코드가 진입점이면 `[진입점]` 으로 쓴다.

## 규칙
- 위치는 source 버전 기준이다. 라인번호는 `git show <SOURCE_SHA>:<경로>` 로 확인한 값을 쓴다 (verify-locations.sh 가 검사한다).
- 구분: 이 PR 이 만든 문제면 `신규`, 이 PR 이 건드리지 않은 기존 코드면 `기존`.
- 신뢰도: 재현 시나리오가 실제로 일어난다는 확신이다. 코드가 그렇게 생겼다는 확신이 아니다. 재현을 코드로 추적했으면 80 이상, 추정이면 80 미만. 80 미만은 최종 결과에서 빠진다.
- 근거 없는 추측성 지적, 린터·포매터가 잡을 스타일 지적은 쓰지 않는다.
- 저장소에 CLAUDE.md 가 있으면(REPO_CLAUDE_MD=yes) 그 규칙 위반도 지적한다. 근거에 해당 규칙을 인용한다.
